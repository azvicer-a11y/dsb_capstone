# Data acquisition

> **The data files are not included in this repository.** A local copy must be placed as described below before running the notebooks.

## Where to put the local copy

```text
data/raw/VALORA_AI_FINAL_COLAB.csv     <- required (SHA-256 d3ddafe1...f973a3; 01_eda.ipynb stops if it differs)
data/raw/valora_cleaned_step2.csv      <- required as well (SHA-256 213990a8...d63424; used in the EDA appendix comparison and checked by the data tests)
```

Then run `notebooks/01_eda.ipynb`, which writes `data/processed/valora_apartments_clean.csv` and the private ID map in `data/private/`, and afterwards `notebooks/02_modelling.ipynb`.

The project needs **two** input files. Everything else is generated by the notebooks.

| Dataset | Source/link | Destination | Size | Acquisition steps | Access/terms |
|---|---|---|---|---|---|
| `VALORA_AI_FINAL_COLAB.csv` | Collected by the project author: public listings from Realitica and Estitor, plus simulated, generated and appraisal rows (see `raw/README.md`) | `data/raw/VALORA_AI_FINAL_COLAB.csv` | 1,643,388 bytes | Obtain the file from the project author. The same file is in the original project repository (`data/` folder of `dsb_capstone-main`). Place it at the destination path; `01_eda.ipynb` checks its SHA-256 and stops if it differs. | Terms of use and redistribution rights are **not documented**; the file contains sensitive appraisal file paths. Kept out of Git by default; see `../docs/privacy_and_data_rights.md`. |
| `valora_cleaned_step2.csv` (comparison only) | The author's earlier partly cleaned version | `data/raw/valora_cleaned_step2.csv` | 1,051,005 bytes | As above. Required: the Appendix of `01_eda.ipynb` and the data tests read it. | As above |
| `settlement_mapping.csv` | Written for this project from the official Monstat 2023 settlement register ("Spisak naselja", monstat.org) | `data/reference/settlement_mapping.csv` | < 10 kB | Included in the repository | Public reference information; evidence per row |

Rules:

- Keep untouched originals in `raw/`. Only `notebooks/01_eda.ipynb` writes cleaned outputs to `processed/`.
- No file here is larger than 25 MB.
- `data/private/` is created locally by the EDA notebook. It holds the link between internal record IDs and platform IDs or URLs, and is never committed.
- If the raw file cannot be shared, the analysis cannot be reproduced without it. The processed file `processed/valora_apartments_clean.csv` (no URLs, IDs or free text) is enough to re-run `02_modelling.ipynb`.
